# PRE-REGISTRATION: extra closed-loop flights without heading (EKF3 and UKF, n = 3 per speed)

Written 2026-11-11, **before any of these flights**, on branch `fwd-camera`. The commit that adds this file is the
registration. User approval 2026-11-11 (scoping report items 3(a) and 3(b)); decision D133 in
`docs/thesis/tier1/decisions_log.md`.

**Purpose.** Each no-heading closed-loop cell of Experiment 1C (H1.8) has n = 1 today, so run-to-run variability is
unmeasured (`numbers.md:464`). This adds flights so that EKF3 and the UKF each have n = 3 per speed. The UKF at full
speed has so far flown only the earlier (pre-jitter-correction) port, so it gets 3 new flights on the final port.

**Frozen material.** `numbers.md` stays frozen. New values go to `docs/thesis/closed_loop_extras/numbers_extras.md`.
Every existing flight and result is kept unchanged. Thesis tables and figures are not regenerated by this work.

  - **Disclosed: six later UKF commits are not built and not flown** (`~/ardupilot_ukf` to `f30f6ffa2f`, 2026-10-10 to

    `f30f6ffa2f` (Replay logging only).
  - **Disclosed: offline and flown flow derotation differ in source and timing, not in whether the bias is removed**
    (checked in the source at `abb0357d`; decision D136):
    - the **offline UKF** derotates each flow frame with its frame-averaged IMU gyro minus its own gyro-bias estimate
      (model correction, 2026-10-09; Table 3.3 row 14);
    - the **flown port** derotates with the gyro the flow driver pairs with each flow sample, `AP::ahrs().get_gyro()`
      averaged over the flow interval (`AP_OpticalFlow_MAV.cpp:39-76`). With the UKF flying (`AHRS_EKF_TYPE 12`), that
      gyro already has the **UKF's own** bias removed (`AP_AHRS_UKF.cpp:32-33`: `gyro_drift = -gyro_bias_rate()`,
      `gyro_estimate = gyro + gyro_drift`);
    - when another backend is active (the UKF as a shadow, or in Replay), the paired gyro carries **that backend's**
      bias, e.g. EKF3's. The later, unflown commit `60c2d83f35` swaps it for the UKF's own in that case and does nothing
      when the UKF flies ("unless it is the UKF", `AP_AHRS.cpp` in that commit). It therefore does not change the
      UKF-flying flights here.
- **Declared harness differences** since the original EKF3 flights (2026-09-29/30), none of which changes the commanded
  trajectory or any estimator:
  - `sim/tools/closed_loop_run.sh` gained UKF/FGO/H/half-world branches; the default EKF3 branch is unchanged, and the

## 3. Criteria, as registered (quoted from the project documents)

- **EKF3** (`docs/thesis/tables/TA_verdicts.md:25-26`): "PRIMARY: no contact before +100 s; contact, if any, on the
  west wall inside [+155, +215] s".
- **UKF** (`TA_verdicts.md:27`; `3.5_experiments.md:59-63`): U1, the backend flies through arming, take-off to ≥ 1.8 m
  and entry into cruise, with no crash, failsafe or loss of control before contact; U2, no contact before +100 s;
  "U3: contact on the WEST wall inside [+146, +218] s" (no contact is a U3 miss as worded); S2, the estimator valid
  throughout.
- **Applied per flight.** Each cell is reported as k/3, counting flight 1 where it exists (EKF3 full, EKF3 half, UKF
  half). The UKF full-speed cell is 3 new flights. **The spread of the contact times within a cell is descriptive.**
- **No comparison across speeds is claimed** (D21).

## 4. Scoring

- `eval/closed_loop_score.py <trial> --set a` (EKF3) and `--set a --est ukf` (UKF, which adds S2), at the registration
  commit. Outputs only under new names: `eval/results/closed_loop_<name>.json`.
- The windows are applied to the scorer's unrounded `t_rel_cruise_s` of the wall contact, inclusive. The scorer's own
  key `contact_if_any_west_in_155_215` is EKF3's window; for the UKF, [+146, +218] is applied.
- **Verdicts are computed on unrounded values.** Rounding is for display only.
- `numbers_extras.md` gets, per cell: the contact times, k/3, the spread (min–max), and the existing n = 1 verdict for
  comparison.
