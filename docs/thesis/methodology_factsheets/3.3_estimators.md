# 3.3 Estimators: fact sheet

Fact sheet for the methodology chapter, §3.3. Line numbers at commit 337c931 (branch fwd-camera). FINAL-STATE facts only; not chapter prose. M = METHODOLOGY.md.

Numbers are cited only from `docs/thesis/numbers.md` (its line in this worktree). A number that numbers.md lacks is tagged with the NOT-IN-numbers.md marker and the place it does appear. Code and parameter-file lines were read at 337c931.

## Facts

- **EKF3, role:** ArduPilot EKF3 is the fixed baseline. It runs on ArduPilot's native `OPTICAL_FLOW` input and derotates the flow internally with its own AHRS gyro, with no pre-processing on our side (CLAUDE.md:969-974). The ArduPilot commit is pinned at `7bac20cbcc` (numbers.md:411).
- **EKF3, flow source:** `FLOW_TYPE 5` (MAVLink), `EK3_SRC1_VELXY 5` (optical flow) and `EK3_FLOW_USE 1` (navigation) are set at flow_ekf.parm:11, :13 and :16.
- **EKF3, flow sensor position:** `FLOW_POS_Z 0.25` (the downward camera's body position, 0.25 m below base_link). It is appended last in the parameter chain (consolidated_rerun.parm:1-8) and is the value used on the re-flown datasets (numbers.md:213).
- **EKF3, GNSS-denied sources:** `EK3_SRC1_POSXY 0` (None), `EK3_SRC1_POSZ 2` (rangefinder), `EK3_SRC1_VELZ 0`, `SIM_GPS1_ENABLE 0` and `GPS1_TYPE 0` (gnss_denied.parm:13, :17, :21, :25, :43). Horizontal position is flow dead reckoning, because POSXY has no optical-flow value (CLAUDE.md:447-455).
- **EKF3, no heading source (the comparison configuration):** `EK3_SRC1_YAW 0` and `COMPASS_USE*/USE2/USE3 0`, with `COMPASS_ENABLE 1` kept so the vehicle can arm, and `EK3_GSF_RUN_MASK`/`EK3_GSF_USE_MASK 3` (gnss_denied_nomag.parm:45-51). The three-way comparison uses the trials flown under this file (M:861-865).
- **EKF3, logged own yaw drift without a compass:** +6.6…+11.1 deg/min, mean ~8.1, over the n = 9 standard-sensor bags (numbers.md:724-725).
- **EKF3, process and measurement noise:** EKF3 runs at literal ArduPilot defaults (M:704-705).
  - Process noise: `GYRO_P_NSE` 0.015 rad/s, `ACC_P_NSE` 0.35 m/s², `GBIAS_P_NSE` 0.001 rad/s/s and `ABIAS_P_NSE` 0.02 m/s/s/s (numbers.md:142-145).
  - Flow: `EK3_FLOW_M_NSE` 0.25 rad/s and `EK3_FLOW_I_GATE` 300, i.e. an NIS gate of 9 (numbers.md:146-147).
  - Range: `EK3_RNG_M_NSE` 0.5 m and `EK3_RNG_I_GATE` 500, i.e. an NIS gate of 25 (numbers.md:148-149).
  - `FLOW_MAX` is a 2.5 rad/s hard reject (numbers.md:150).
- **EKF3, prediction period:** `EKF_TARGET_DT` 0.012 s with `SCHED_LOOP_RATE` 400 gives 5 frames, i.e. a prediction dt of 0.0125 s (80 Hz). This is derived, not logged (numbers.md:182-185).
- **EKF3, pseudo-yaw (synthetic yaw):** EKF3 checks for a fusion opportunity every 140 ms and fuses only when the quaternion-covariance trace exceeds 0.01 (numbers.md:158-159; M:903-909).
- **EKF3, flow timing:** EKF3 fuses flow 31–44 ms before capture (median 36). Its hard-coded 100 ms flow interval meets our 30 Hz flow (numbers.md:231).
- **EKF3, evaluation:** flights fly on simulator truth (`AHRS_EKF_TYPE 10`, set explicitly at consolidated_rerun.parm:11). EKF3 is evaluated offline from its own logged state (`XKF1`), so every condition has one fixed trajectory (CLAUDE.md:793-802).
- **EKF3, invalid output:** with no flow, EKF3 flags its position invalid (transition: +0.9…+1.1 s after loss; blank: from take-off). While invalid its output is exactly the origin, and that output is not scored (numbers.md:245-246).
- **EKF3, offline forward-camera comparison:** EKF3 is the fixed no-heading baseline, and only the UKF and the FGO get forward-camera arms (M:2884-2888). The reasons (M:2906-2943):
  - EKF3 has one downward flow sensor;
  - ExternalNav yaw needs a position in every message and has a noise floor;
  - EKF3 has no input for yaw rate;
  - the recorded logs lacked replay records.
  - **REOPENED (D131/D132):** the last reason is stale (erratum E1). EKF3 + camera heading is now evaluated offline via ArduPilot Replay, as a separate, DESCRIPTIVE arm (no verdict); every value carries EKF3's own unconditional 5° `angErr` floor [NOT IN numbers.md: ekf3_heading_replay/numbers_ekf3_heading.md:5], and a matched 5° UKF/FGO arm is run separately from the stored 0.148°/0.126° heading-sigma arms (numbers.md:374). On `fwdplainc_tex` no heading benefit is claimed for any estimator on this arm either: the forward-camera heading measurement itself FAILED Phase 3 validation on that floor (numbers.md:301).
- **EKF3, closed loop with heading (ExternalNav yaw only):**
  - Settings: `VISO_TYPE 1`, `EK3_SRC1_YAW 6`, `VISO_QUAL_MIN 50` (which accepts exactly the frozen heading validity) and `VISO_YAW_M_NSE 0.05` (closedloop_heading.parm:8, :10, :12, :15).
  - The effective yaw σ is set by EKF3's floor, `yawAngErr = MAX(angErr, radians(5))` (numbers.md:402). The `VISO_YAW_M_NSE` floor is ≥ 0.05 rad (numbers.md:405).
  - Delay: `VISO_DELAY_MS 38` at RTF 1.0 with the C++ node (closedloop_heading.parm:19) `[NOT IN numbers.md: closedloop_heading.parm:19]`, and 25 ms at half real-time (RTF 0.5) (numbers.md:464; closedloop_heading_half.parm:20).
  - The AHRS selects EKF3 with `AHRS_EKF_TYPE 3` (closedloop.parm:4). The UKF uses 12 and the FGO 13 (closedloop_ukf.parm:4; closedloop_fgo.parm:4).
- **EKF3, tag fixes (Experiments 2 and 3):**
  - Source settings: `VISO_TYPE 1`, `EK3_SRC1_POSXY 6` and `EK3_SRC1_YAW 6` (ExternalNav position and yaw) (tags_extnav.parm:4-6).
  - Noise: `VISO_POS_M_NSE 0.05` and `VISO_YAW_M_NSE 0.05`, giving an effective yaw σ of 5° (tags_extnav.parm:7-8) `[NOT IN numbers.md: tags_extnav.parm:7-8]`.
  - Delay: `VISO_DELAY_MS 15` (numbers.md:542; tags_extnav.parm:10). This is a declared deviation from the delay rule (M:10509).
  - EKF3 keeps its own gates and its 10 s timeout behaviour (M:10137-10139; numbers.md:538-539).
- **EKF3, tag hold (Experiment 5):** ExternalNav position and yaw from the wall tag (h_extnav.parm:3-7).
  - `VISO_POS_M_NSE 0.02` (= σ_pos from the wall-tag characterisation, numbers.md:600).
  - `VISO_DELAY_MS 31` (numbers.md:602; h_extnav.parm:11).
- **UKF, state:** 15 states in ENU/FLU with ZYX Euler attitude: position, velocity, attitude, a gyro bias and an accelerometer bias. The biases are in delta form, matching EKF3 (src/estimators/ukf_core.py:3-8).
  - Sigma points are Van der Merwe, with α = 1e-3, β = 2, κ = 0 (ukf_core.py:48, :51) `[NOT IN numbers.md: ukf_core.py:48]`.
- **UKF, prediction period:** the onboard port predicts at 12.5 ms (DAL frames). The offline UKF predicts at 15.00 ms, its actual accumulated IMU interval (numbers.md:186).
- **UKF, process noise:** the same per-second densities as EKF3 and the FGO. They are EKF3's values at DT_REF = 12.5 ms, and the offline per-step forms are scaled by DT_REF/dt (numbers.md:187; ukf_core.py:21, :25-37; M:9567-9580).
- **UKF, flow and range updates:** EKF3's noise and gates, copied unchanged: `FLOW_M_NSE` 0.25, `FLOW_GATE` 300, `FLOW_MAX` 2.5, `RNG_M_NSE` 0.5, `RNG_GATE` 500, and range limits 0.05–40 m (ukf_core.py:44-45; numbers.md:146-150).
  - Each update is a scalar update with an EKF3-style NIS test (ukf_core.py:207-216).
- **UKF, pseudo-yaw cap:** a zero-innovation yaw update, R = 0.5 rad [NOT IN numbers.md: ukf_core.py:46-47], checked every 140 ms. It fires only when the Euler attitude-covariance trace exceeds 0.04 rad², which is EKF3's quaternion 0.01 mapped exactly (numbers.md:158-160; ukf_core.py:46-47, :271; M:903-917).
  - Measured firing: an attitude-covariance trace of 0.029 (Euler) and a firing rate of about 1% (numbers.md:163).
- **UKF, ground-proximity flow rule:** EKF3's rule, used with EKF3's own thresholds (M:7038-7062). Before take-off is detected and below 0.5 m height above terrain, flow is replaced by zero and still fused. The FGO shares the rule (src/estimators/ukf_replay.py:127-130; measurement_models.py:260).
- **UKF, flow derotation:** derotates with the gyro averaged over the flow frame, minus the UKF's own gyro-bias estimate. This bias-corrected form is the default in both offline harnesses (M:12721-12726; ukf_replay.py:171-172).
- **UKF, Cholesky jitter:** none on the first factorisation attempt. Only on failure does it retry at 1e-12, 1e-9 and 1e-6, and the fallback never fired on real data (M:12408-12420; ukf_core.py:52-57).
- **UKF, initialisation:**
  - Roll and pitch come from gravity levelling over the first 0.5 s. Height is the first valid range + 0.12 m. Yaw starts at 0 (ukf_core.py:306-317; ukf_replay.py:84-106).
  - Initial σ: yaw 1°, roll and pitch 5° (numbers.md:700; ukf_core.py:321).
  - Initial bias σ: EKF3's 0.043633 rad/s gyro and 0.2 m/s² accelerometer, scaled by dt into delta form (ukf_core.py:314-315 [corrected from :313-314, a one-line drift at this commit]) `[NOT IN numbers.md: ukf_core.py:314-315]`.
- **UKF, validity rule (onboard port):** position and velocity are declared invalid in either case:
  - (a) no flow has been accepted for more than 5000 ms, EKF3's relative-aiding timeout;
  - (b) the horizontal-velocity 1σ exceeds 0.5 m/s.
  - Sources: M:5366-5374. The 5 s timeout is in numbers.md:491; the 0.5 m/s bound is `[NOT IN numbers.md: M:5372]`.
- **UKF, hindsight:** the "smoothed UKF" is an unscented RTS smoother over the UKF's predict nodes (M:10146; ukf_core.py:159).
- **FGO, solver:** a GTSAM 4.2.1 [NOT IN numbers.md: CLAUDE.md:71] `BatchFixedLagSmoother`. It solves with Levenberg–Marquardt, capped at 2 iterations and warm-started (numbers.md:451; src/estimators/fgo/fgo_core.py:84-90).
  - Against full LM, the cap changes position by at most 0.11 m, RMS 0.029 m (numbers.md:452).
  - Extension experiment E4 (pre-registered; claim C5, ruling 2026-10-24): cap 2 was also compared with cap 10 at every window from 0.25 to 5 s (numbers_tier1.md:385) on two room flights (T_A_r1, T_D_r1). No convergence flag was raised: the largest RMS reading was 0.0009 m, against the 0.029 m threshold (numbers_tier1.md:515, 528). Cap 10 is not full LM (tier1/e4_results.md §3; tier1/scores/E4_verdicts.json:convergence).
  - Keyframes are on the IMU clock at 30 Hz, period 33.3 ms (numbers.md:380; FGO_DESIGN.md:769). Every IMU sample is fed to the preintegration (CLAUDE.md:719-722).
- **FGO, fixed-lag window:** 0.25 s, a declared configuration choice. In the corridor configuration, 0.25 s was the largest window within the 33 ms budget; on the tag-room flights 0.5 s also fitted (27–28 ms) (numbers.md:209, 440; M:702-709; ruling 2026-10-24, Q2; 27–28 ms [NOT IN numbers.md: tier1/e4_results.md:169, median step after the anchor at W = 0.5 s, 12 flights; DIAGNOSTIC]).
  - The corridor sweep is DIAGNOSTIC and measured before the thread-limit fix (numbers.md:444). No general claim is made about the largest window (ruling 2026-10-24, Q2).
  - Extension experiment E4 (pre-registered; claim C4) on the 12 Experiment 2 flights: the median step time rose strictly with the window on every flight (P-E4.1 PASS 12/12, numbers_tier1.md:525); it was within the budget at 0.25 s and over it at 1, 2 and 5 s on 12/12 flights (P-E4.2 PASS) (numbers_tier1.md:526). A longer window did not improve live accuracy at the registered count (H-E4.3 FAIL 7/12, a null result, not a proof that accuracy is independent of the window) (numbers_tier1.md:527; tier1/e4_results.md §1, §3–§4; tier1/scores/E4_verdicts.json).
  - The code default is 1.0 s, so the window must be passed explicitly (fgo_core.py:57; src/estimators/fgo/fgo_replay.py:125).
  - The pre-registered window was 1.0 s (FGO_DESIGN §6; M:706).
- **FGO, IMU noise conversion:** σ_c = NSE·√dt at dt = 0.0125 s (numbers.md:151-152).
  - Continuous-time covariances: accelerometer 1.53125×10⁻³, gyroscope 2.8125×10⁻⁶, accelerometer bias 5.0×10⁻⁶, gyro bias 1.25×10⁻⁸ (numbers.md:153-156; fgo_core.py:26-30).
  - `integrationCovariance` is about 1e-8·I and has no EKF3 counterpart (numbers.md:157).
  - Gravity: `MakeSharedU(9.81)`, Z up (fgo_core.py:26).
- **FGO, `biasAccOmegaInt`:** set to zero (fgo_core.py:32-35). GTSAM 4.2.1 adds this term as IMU white noise at every sample, so the initial bias uncertainty belongs in the B(0) prior only (M:12046-12057). This was a model correction to the sensor-noise model, not tuning.
- **FGO, measurement noise:** flow σ 0.25, range σ 0.5 m and yaw-cap σ 0.5 rad, all EKF3's values (fgo_core.py:97-99). The flow and range factors share the `h_flow` code with the UKF (`src/estimators/measurement_models.py:77-120`).
- **FGO, yaw cap:** variance-gated as in EKF3 and the UKF: checked every 0.14 s, firing when the predicted attitude trace exceeds 0.04 rad² (fgo_core.py:51-52; M:12467-12471).
  - The FGO checks only on keyframes, about 167 ms apart against about 150 ms. This difference is structural (M:12471).
- **FGO, initial uncertainty (the initial-uncertainty correction):** initial yaw σ 1° and roll/pitch 5°, both equal to the UKF's (fgo_core.py:44, :48; numbers.md:700).
  - EKF3's own values are 0.1 rad and 5.73° (numbers.md:700).
  - Caveat: the on-ground heading offsets (~3°) exceed 1° at 3σ (numbers.md:700).
  - Which flights had which priors: the ORIGINAL flown FGO corridor and hold results used the original priors (yaw 1e-3 rad, roll/pitch 2°; numbers.md:36-37, :464), now relabelled "superseded: original priors" and not counted (`refly_priors/numbers_refly.md:376`). A re-fly on the corrected priors (yaw 1°, roll/pitch 5°, matching the UKF; numbers.md:700) is now the current FGO corridor (H1.8, n = 3) and hold row (`refly_priors/numbers_refly.md:16-23, 97`). The FGO safety re-tests on the corrected-priors node used the new priors too (numbers.md:36-37, :464).
  - Initial bias σ, as for EKF3: gyro 0.043633 rad/s, accelerometer 0.2 m/s² (fgo_core.py:39-40 [corrected from :38-39, a one-line drift at this commit]) `[NOT IN numbers.md: fgo_core.py:39-40]`.
- **FGO, builds:** the final FGO is the noise fix plus the gated yaw cap. The ablation build is the noise fix with the cap ungated (numbers.md:466; thesis_vocabulary.md:118-121).
  - The onboard C++ node passed the pre-registered equivalence band on the textured bag (4.1e-4 mm) and failed as worded on blank and transition, where the Python FGO runs away (M:10734-10746).
  - Runaway (†) FGO magnitudes are not bit-reproducible across BLAS builds (numbers.md:703-714).
- **FGO, robust heading variant (Experiment 1B robust weighting):** a Cauchy M-estimator with k = 2.385, chosen on the calibration bags (numbers.md:509; fgo_core.py:101-106).
- **FGO, hindsight tracks:**
  - Experiments 2 and 4: the "FGO whole-flight batch", one LM run of at most 50 iterations over every factor the live FGO received (M:10142-10144) `[NOT IN numbers.md: M:10143 (≤ 50 iterations)]`.
  - Experiment 3: a separate "keyframe FGO (loop closure)". It keeps the full history in plain iSAM2 with no marginalisation, uses tag landmarks (x, y, yaw), has no yaw cap after the anchor, and identifies the no-loop-closure arm by giving every tag pass a new landmark (M:10459-10480).
- **FGO, iSAM2 in the fixed-lag smoother:** unusable. The marginalisation cascades after about 590 keyframes when a Python `CustomFactor` is in the graph (numbers.md:454; FGO_DESIGN.md:547).
- **Heading measurement, method (frozen):**
  - LSD line segments: shorter than 15 px, or within 5° of horizontal or vertical, are discarded.
  - The vanishing point comes from RANSAC (300 iterations, length-weighted, seeded per frame), refined by weighted least squares.
  - ψ = atan((u_vp − cx)/fx).
  - Three priors: the VP must be inside the image, within ±5° of the horizon row, and supported on both sides.
  - Roll and pitch are not compensated (M:2649-2670).
  - Sources: M:2649-2670; src/forward_camera/fwd_measure.py.
- **Heading measurement, validity:** a heading is valid iff its balanced support is ≥ S_MIN = 200 px. Otherwise the output is "no measurement", which also gives the end-wall dropout (numbers.md:372; M:2672-2676).
- **Yaw-rate measurement:** Shi-Tomasi corners in a box around the previous frame's VP, tracked by pyramidal LK. ω = median(Δu)/fx/Δt, valid with ≥ N_MIN = 5 corners (numbers.md:373; M:2678-2688).
- **Calibration and validation split:**
  - Calibration used the six camera calibration flights only, with a pre-registered grid and selection rule.
  - Validation used the 18 dataset bags with frozen parameters and no re-tuning (M:2690-2707).
  - Ground truth is used for evaluation only (M:2644-2646, :2709-2715).
- **Frozen parameters:** inlier tolerance 0.5°, S_MIN 200 px, box 80 px, N_MIN 5. OpenCV 4.6.0 and numpy 1.26 are pinned (numbers.md:338).
- **Accuracy bar (pre-registered, per bag over cruise):**
  - Heading: availability ≥ 70%, |bias| ≤ 0.5°, noise ≤ 1.0°, outliers ≤ 5% (|error| > 3°).
  - Yaw rate: availability ≥ 70%, |bias| ≤ 0.05 deg/s, noise ≤ 1.0 deg/s, outliers ≤ 5% (|error| > 3 deg/s).
  - Source: M:2725-2730 `[NOT IN numbers.md: M:2727-2730 (bar thresholds)]`.
- **Validation result (H1.2):**
  - Heading: textured-wall camera dataset 9/9, plain-wall camera dataset 6/9 (it fails over the checkerboard floor) (numbers.md:330).
  - Yaw rate: textured-wall 9/9, plain-wall 3/9 (numbers.md:331).
  - Second validation on the camera calibration flights: heading 5/6, yaw rate 4/6 (numbers.md:332).
  - Per-world availability, sd and outliers: numbers.md:339-342.
- **Heading fusion, offline (UKF and FGO only):**
  - Model h_ψ = yaw, with the innovation wrapped; h_ω = ω̄_z − b_g,z (M:2975-2990).
  - Noise from the static yaw sweep: σ_ψ 0.148° (textured walls) and 0.126° (plain walls); σ_ω 0.162 deg/s (numbers.md:374-375).
  - Gate ν²/S ≤ 9 in both estimators (numbers.md:376), implemented as `FWD_CHI2_GATE = 9.0` and `FWD_SIGMA` (src/estimators/measurement_models.py:186, :191-192).
  - The FGO runs a 30-dimensional gate-only filtering covariance recursion for its gate (numbers.md:379).
  - No ground truth, position or world knowledge enters any gate (M:2970-2973).
- **Live heading node (closed loop):** the frozen Phase 3 heading code and parameters run on the Phase 3 stack, OpenCV 4.6.0 and numpy 1.26 (M:4717-4735).
  - A C++ port of the per-frame computation passed every pre-registered equivalence band on 10,238 frames: max |Δψ| 5.2e-13° and identical support (M:6046-6056).
  - The FGO applies a heading a median 17 ms and at most 33 ms after capture; this was closed as negligible (numbers.md:486).
- **Tag measurement (Experiments 2–5):**
  - Detector: pupil_apriltags tag36h11, giving the vehicle pose `T_world_body = T_world_tag · T_tag_cam · T_cam_body` (M:10018-10020).
  - Accuracy at 2.26 m: detection 100% of fully visible tags; central-third position p95 40 mm and yaw p95 0.10°; 5.6 ms per frame (numbers.md:540-541).
  - Validity rule, shared by all three estimators: a fix is sendable only if its centre is in the central third of the image, and only one fix per image is sent (M:10048-10050).
  - UKF and FGO tag model: h = (p_E, p_N, yaw) with σ_pos 0.05 m and σ_yaw 5°, matching EKF3's effective noise; no gate in the UKF or FGO (M:10129-10136) `[NOT IN numbers.md: M:10130 (σ 0.05 m / 5°)]`.
- **Wall-tag measurement (Experiment 5):**
  - Detection 95.8% of in-view frames with 0 wrong ids; horizontal p95 15–24 mm; yaw p95 0.4–0.7°; σ_pos 0.02 m (numbers.md:597-600).
  - Shared validity rule, applied identically to all three estimators: in flight, camera-to-tag 0.9–2.8 m; on the ground while disarmed, any range (M:11612-11616) `[NOT IN numbers.md: M:11614 (0.9–2.8 m)]`.
- **E3 extension experiment: robust tag-factor FGO (ESTIMATOR VARIANT, never merged into the thesis FGO).** A Cauchy
  M-estimator, k = 2.385, wraps the diagonal tag landmark noise model (`gtsam.noiseModel.Robust`) on the 3-vector

  UKF's final filtered landmark state (`e6_preregistration.md:147-156`). Without the flag the code path is

  result (P4 PASS 3/3 for both estimators; P2 FAIL for both; numbers_tier1.md:700, 703).

## Appendix candidates

- **EKF3 prediction-dt source trace:** `EKF_TARGET_DT`, the accumulation, the trigger and the `dt` constrain, at `7bac20cbcc` (CLAUDE.md:528-546).
- **GTSAM noise-conversion derivation:** includes the delta-to-rate bias-unit step, so all four terms reduce to σ_c = NSE·√dt (CLAUDE.md:659-702).
- **Pseudo-yaw threshold verification:** the 0.01 → 0.04 mapping is checked three independent ways, with EKF3's logged quaternion covariance at median 0.0093 (numbers.md:161-162; M:911-926).
