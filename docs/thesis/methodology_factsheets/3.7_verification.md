# 3.7 Verification process

Fact sheet for the methodology chapter, §3.7. Line numbers at commit 337c931 (branch fwd-camera). FINAL-STATE facts only; not chapter prose. M = METHODOLOGY.md.

## Facts

- **Pre-registration rule (standing from 2026-09-24).** Every criterion is labelled PRIMARY (it tests the confound
  directly) or DIAGNOSTIC (reported, never a gate). Only primary criteria can stop a phase (M:1142-1153).
- **Band margins.** No band uses the bare observed range. Each band states its margin and the basis for it: a
  physical tolerance, or the n = 3 range widened by a stated factor. It also says why a value outside the band would
  indicate the confound (M:1149-1152).
- **Why n = 3 ranges are not bounds.** With three repeats, a fourth run lands outside the observed range with
  probability 2/(n+1) = 50% (numbers.md:208; M:131-134).
- **The noise floor replaces "n = 3 range ± one range-width"** as the basis for future textured bands. The existing
  bands are not re-scored retrospectively (numbers.md:736-738).
- **Scope-control rule.** Before any work outside the phase brief, two questions are asked: does it change a thesis
  claim, and would a reviewer's objection stand without it? If both answers are no, the work becomes one line on the
  open-items list. Diagnostics are reported, never investigated on the spot (M:1155-1164).
- **Keep-and-record rule for primary misses.** A bag is excluded only for an input defect. Excluding or re-flying a bag
  because an estimator performed badly on it, without a defect, would be selection bias. The miss stays recorded and
  is neither re-scored nor waived (M:2122-2131).
- **Baseline corrections are batched.** Corrections to the standard-sensor baseline are batched into one consolidated
  re-run before the results chapter, not restated one at a time (M:1166-1171).
- **The consolidated re-run is a correction, not a tuning pass.** No parameter changes beyond the listed corrections;
  any result that changes direction is flagged; after it, results are frozen for writing (M:3774-3781).
- **Empirical re-run gate (standing control).** Every measurement-model, gate or noise change is gated on a
  from-scratch estimator re-run, and reverted if the outcome metric degrades. Offline residual diagnostics and
  innovation correlations are necessary but not sufficient evidence (M:438-448).
- **The re-run gate caught two offline-evidenced changes:** the lateral-flow sign flip and the interval-averaged gyro
  (M:450-451).
- **Phase 0 reproducibility gate.** Every published figure is regenerated from stored data with one committed script
  before it is built on (M:550-552). It caught the mixed-window three-way table (M:20-26).
- **Phase 0 smoke test, pre-registered before flying:** one new textured trial on the unchanged configuration. It
  passes on three conditions: the pipeline completes, every topic's sim-time rate is within the stated tolerance of
  the textured mean, and cruise ATE is inside the widened n = 3 range (M:136-145).
- **IMU-gap rule.** A gap before arming moves the UKF/FGO replay start to after the gap. Any gap after arming makes
  the bag unusable for the replay estimators, while EKF3 is still scored (M:1985-1992; `eval/imu_gap_check.py`).
  Applied to the re-flown bags: 39 `ok`, 3 `trim`, 0 `unusable` of 42 (numbers.md:326).
- **Final consolidated re-run (2026-10-09/10).** Run by `eval/final_rerun_pipeline.sh`, one stage per call
  (M:12691-12693).
  · Rebuilt job lists are confirmed by REPRODUCTION, not by eye: at least one representative job per list is re-run
    with the OLD code and must reproduce the stored output byte-identically or to the stored precision
    (M:12703-12706).
  · The EKF3-unchanged checks are FATAL gates (M:12708).
- **FGO-only re-run (2026-10-10).** All hard gates pass with 0 differences; EKF3 and the UKF are unchanged; only the
  FGO changed (numbers.md:31-32; M:13342-13345).
- **Old-vs-new comparison.** Every re-run writes an old-vs-new file (`eval/results/final_old_vs_new.md`,
  `final2_old_vs_new.md`). Each DIRECTION flag is checked (a real change or a mapping artefact) before any number is
  quoted (M:12778-12782, M:13350-13353; numbers.md:34).
- **Attribution.** The corrections were applied jointly and are not attributed individually. The exceptions are the
  directly traced plain-wall case and the ruled outdoor–indoor partial attribution (numbers.md:35-36,
  numbers.md:693).
- **Verification flights are SHORT and never result data.** They use the shortest profile that exercises the thing
  checked, and each spec states why that length suffices. Full-length profiles are only for pre-registered,
  result-producing experiments (M:13096-13101).
- **Simulation results FROZEN (2026-10-11).** No new result experiments or re-runs. Short verification flights for
  real-flight readiness are allowed (M:13399-13400).
- **Provenance: numbers.md is the single source of quotable values.**
  · Values cited to M:/C:/P: are copied verbatim, and values traced to a stored result file are rounded once
    (numbers.md:3-4).
  · Its `M:L…` source cells point into the frozen snapshot `docs/thesis/export_2026-09-29_563a989/`, not into the
    current METHODOLOGY (numbers.md:6-11).
  · Every row carries a status: CURRENT, DIAGNOSTIC, ESTIMATE, CURRENT (pre-registered), and others
    (numbers.md:15-19).
  · Superseded values appear only in the superseded section, each with what superseded it (numbers.md:20).
- **Untraceable thesis-facing values.** Of the 769 numeric tokens with no stored-result trace, 43 quantities appear in
  thesis-facing material. Each has a written source of a ruled type (results file, METHODOLOGY line,
  pre-registration line, parameter file), except one quantity with only a CLAUDE.md source and one with none
  (`docs/thesis/thesis_values_provenance.md:9`, :45-52, :104-112).
- **Phase 5 decomposition row provenance record** (accepted by ruling). The record traces the row from script,
  pipeline logs, job lists and file mtimes, with nothing recomputed. It gives two verdicts: (1) Phase 5 read the final
  UKF and FGO Phase 4 outputs, and (2) no later correction touched either Phase 4 path (numbers.md:1312-1400).
- **Thesis rounding rule.** Each displayed number is the full-precision stored value rounded ONCE, to the printed
  precision, half away from zero. It is read through its shortest decimal form (`decimal.Decimal(str(x))`,
  ROUND_HALF_UP) (`eval/figs_thesis.py:79-89`; `docs/thesis/methodology_definitions_draft.md:191-202`).
- **numbers.md displays the same single rounding.** The double-rounded rows were corrected in place, with the old rows
  kept in a Superseded block (numbers.md:758-773; M:14229-14236).
- **The exact cross-check.** For each displayed value, the stored full-precision value rounded once by `rd()` must
  equal the typed numbers.md string (or METHODOLOGY where numbers.md has no row) character for character. There is
  no numeric tolerance and no last-digit acceptance (`eval/figs_thesis.py:100-105`; M:14237-14238).
  · A failed check marks the figure or table FLAGGED in the index (`eval/figs_thesis.py:14-16`,
    `eval/figs_thesis.py:116-123`).
- **The frozen results pack is not touched.** Its tolerant checker (`eval/figs_final_pack.py`) is frozen and
  unchanged (M:14239; `eval/figs_thesis.py:104`).
- **numbers.md CONTENT-FROZEN (2026-10-16).** No in-place edits. Any change is a dated erratum entry appended under
  "## Errata" (numbers.md:3, numbers.md:1407-1411; M:14241-14252).
- **Erratum entry format.** Each entry gives the frozen text verbatim, the corrected text, the reason, the source and
  the ruling. An earlier entry is never edited or deleted; a new entry supersedes it (numbers.md:1414-1423).
- **At 337c931 there are no errata** ("(No entries yet.)", numbers.md:1425).
- **`tools/check_numbers_frozen.py`.** It hashes everything above the single "## Errata" heading with SHA-256 and
  compares the result with `FROZEN_SHA256` (`tools/check_numbers_frozen.py:18`, :22-35).
  · The frozen-commit token in the header is masked, so recording the SHA does not change the hash
    (`tools/check_numbers_frozen.py:6-8`, :30-31).
  · If the recorded commit resolves, its content is also compared (`tools/check_numbers_frozen.py:52-62`).
  · Exit status is 0 if unchanged, and 1 if changed or if the Errata heading is missing or duplicated
    (`tools/check_numbers_frozen.py:11`).
- **Freeze check at 337c931:** "PASS: numbers.md above '## Errata' sha256 6a77b9ab… (frozen 6a77b9ab…)" and "ok: frozen
  commit 669f099 has the frozen content" (run of `tools/check_numbers_frozen.py`; hash constant at
  `tools/check_numbers_frozen.py:18`).
- **C++ FGO port equivalence band, pre-registered.** Same keyframe count, |Δp| ≤ 1 mm and |Δyaw| ≤ 0.01° per
  keyframe, against the Python thesis FGO on the same bags (M:10736-10738). Accepted in the aided regime only, where
  it passed (M:10758-10760).
- **Reproducibility of diverging (unaided) FGO results.** They are not bit-reproducible across BLAS builds, so they are
  cited as evidence of divergence with their order of magnitude, not as precise values (marker †). Aided results are
  bit-reproducible across builds (numbers.md:703-714).
- **Edit guard and flight lock (process controls).** A PreToolUse hook refuses any edit to a source file used by a
  running job (`tools/edit_guard.py:2-15`); flights hold `FLIGHT_LOCK` (`tools/flight_lock.sh`, used e.g. at
  `tools/test_watch_failclosed.sh:5-6`).
- **Tier-1 checksum guard (extension experiments E2–E6; new verification mechanism).** `tools/tier1_checksum_guard.py`
  `snapshot`s then `verify`s a manifest of result data — every `~/thesis_data/trials/T_*` file, every other trial's
  outputs except its recorded bag, `~/thesis_data/batches/`, and `eval/results/` — never code and never documents
  (`numbers.md`, the frozen pack, `METHODOLOGY.md`; scope decided 2026-10-22) (`tier1/preregistration.md:707-744`).
  Any difference is **STOP AND REPORT**: exit 1, every changed/missing/added file listed, no further runs until
  ruled (`tier1/preregistration.md:712-713`). Run before the first stage of each experiment and after its last run;
  E6 additionally snapshots/verifies around each of its sub-stages (`numbers_tier1.md:26-38, 590-601`). Every
  verify across E2–E6 and the ablation returned **IDENTICAL**, 13,253 files (`numbers_tier1.md:30-38`;
  `ablation_numbers.md:21-22, 32`).
- **Supplementary code snapshots for new estimator code.** Because E5's landmark UKF and E6's `--tag-map` flag did
  not exist at the main snapshot, each takes its own `snapshot --paths <files>` immediately before its first
  validation run, verified after the last result run of that experiment (`tier1/preregistration.md:745-750`;
  `numbers_tier1.md:37-38`).
- **Reproduction gates stand in for a code snapshot on unchanged paths.** G0-L (Experiment 3 LC replay), G0-UKF
  (Experiment 2 UKF replay) and G-E4/G-E4′ (the 0.25 s FGO window) each require byte-identical reproduction of a
  stored, already-verified result before any new run on that path counts; only the genuinely new code (E5's
  landmark model, E6's `--tag-map`) is judged by a numerical tolerance instead
  (`tier1/preregistration.md:758-790`; `numbers_tier1.md:44-50, 614-617`).
- **Exact cross-check scripts (E2, E3, E5, E6; independent re-derivation, not just string copy).** Each experiment's
  results page is generated by a script that re-computes every printed value from the stored score jsons and
  requires it to match the hand-written prose by string equality: `stage2d/crosscheck.py` (E2), `stage2e/crosscheck.py`
  (E3, 0 mismatches), `stage2c/crosscheck.py` (E5) and `e6/check_e6_prose.py` (E6, re-builds every table row and every
  hand-typed number in `e6_results.md`, `e6_numbers.md` §Results and the Stage 2 handover, 0 mismatches)
  (`e3_results.md:23-24`; `e6_results.md:11-14`). The ablation's own checker is `check_ablation.py`, run after every
  job batch (`ablation_numbers.md:17`).
- **Identity/gate checks before any extension-experiment score counts.** E4's G-E4 (§3.3/3.9) and the ablation's own
  identity gate (rung r0 must reproduce the stored trajectories byte-for-byte on 12/12 bags before any other rung is
  scored) are the same pattern applied to a parameter sweep rather than a one-off reproduction
  (`ablation/preregistration.md:17-19`; `ablation_numbers.md:27-29`).
