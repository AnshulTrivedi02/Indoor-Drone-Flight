## How it ran (same pattern as Stage 2a)

- **Drivers:** `~/thesis_data/tier1/stage2c/driver_val.sh`, then `driver_res.sh`. Both are serial, one
  `heavy.py --wait-s 1800` per job, and both stop on any non-zero rc.
  - `driver_val.sh` judged each run immediately with `e5_val_compare.py --delta-rmse` and stopped unless the judge
    json's `PASS` was true.
  - `driver_res.sh` refused to start unless `timing.tsv` held `ALLDONE_VAL` and 36 PASS judges.
- **Jobs:** `stage2c/jobs/*.sh`, with the thread variables at 1 (TBB included) and `~/venv-evo`.
- **Logs:** `stage2c/logs/`. **Timing:** `stage2c/timing.tsv`.
- **Procedural deviation (`run_jobs_resumable.sh` not used; nice 19):** recorded in `numbers_tier1.md` §Deviations
  BEFORE the first V-E5 run.
- **Scoring:** `~/venv-evo/bin/python eval/l_score.py T_A_r<i> --in-root ~/thesis_data/tier1 --prefix lc_ukf --suffix
  _t245 --json docs/thesis/tier1/scores/e5_T_A_r<i>.json`. Its output is in `docs/thesis/tier1/stage2c/l_score.log`.
  The lap bounds equal the stored expL ones.
- **Verdicts:** `stage2c/e5_verdicts.py` writes `scores/e5_verdicts.json`.
  - It reads the score jsons, `eval/results/expL/T_A_r<i>_t245.json` (FGO) and the run `stats.json` invariants.
  - Every input value is stored with its source key, and comparisons use the unrounded values.
