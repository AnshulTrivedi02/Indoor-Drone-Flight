**The 5 named defects, fixed:**

1. **B01** (two touching value labels, "0.055"/"0.061" in the 4-tag group): the old stagger used a FIXED per-
   estimator vertical offset (`YOFF = {"EKF3": 0.0115, "UKF": 0.0025, "FGO": 0.0025}`), which assumed EKF3's bar is
   always the taller of the two - true in 3 of 4 conditions but false in the 4-tag condition (EKF3 0.055 < UKF
   0.061), where it put both labels at nearly the same height a small horizontal offset (0.27 bar-widths) apart,
   and they touched. Replaced with a rank-by-actual-bar-height algorithm: sort the 3 estimators by their OWN value
   in that group, then push each label up only as far as needed so it clears the next-taller bar's label by a fixed
   `MIN_GAP` (0.013 m) - correct regardless of which estimator happens to be shorter. Re-checked all 4 groups by
   hand against the new render: no two labels closer than roughly 0.011-0.013 m vertically in any group.
2. **B02** (legend sitting on the y = -3 track edge): the three flights' true path touches all four edges of the
   6 m square, including the bottom edge where the old `ax.legend(loc="lower right", ...)` sat - there is no
   genuinely empty spot inside the axes. Moved to `fig.legend(loc="lower center", ..., bbox_to_anchor=(0.5, -0.02))`
   with `fig.subplots_adjust(bottom=0.14)`, the same below-axes placement B03 already used - now entirely outside
   the data.
3. **B04** (empty EKF3-hindsight panel; bold in-axes labels sitting over the data): two separate fixes applied to
   the same figure. (a) The "empty" panel was not actually empty - the code drew its grey GNSS-off `axvspan`
   shading into it before checking `nn is None`, so it showed a floating grey rectangle with the axis turned off
   rather than a genuinely blank cell. Reordered so the `None` branch calls `ax.axis("off")` and `continue`s before
   any shading or data is drawn, producing a plain blank cell - confirmed empirically that a `loc="left"` title set
   AFTER `ax.axis("off")` on a DIFFERENT axes still renders (used for the "hindsight" column header, which sits
   above `axs[0, 1]`, not the blank cell itself). (b) The five bold, colour-matched "EKF3, live" / "UKF, hindsight"
   / etc. in-axes text labels (top-left corner of each panel, `weight="bold"`) were removed entirely and replaced
   with row headers - `ax.set_ylabel("EKF3")` / `"UKF"` / `"FGO"` on the left column only, regular weight, outside
   the plotted data (the common brief's explicitly-allowed "estimator names" direct label, and "row headers outside
   the axes" option) - plus the existing `"live"` / `"hindsight"` column titles, shortened from the earlier
   `", solid"` / `", dashed"` suffixes (moved into the caption instead, matching the already-established house
   precedent in `eval/figs_thesis.py`'s FIG 7 L restyle comment: "per-panel titles shortened to panel labels (a)/(b)
   only ... text notes are removed rather than relocated").
4. **B06/B07** (in-plot "limit for the mean: 50 mm" / "tightest limit: 50 mm" registered-limit text): both
   `ax.text(...)` calls removed outright. The dashed reference line (`ax.axhline(50, ...)`) is kept undecorated;
