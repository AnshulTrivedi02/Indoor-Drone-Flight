## 2. Derotation (D18 ruling): the UKF's own bias-corrected gyro, the same rule in flight and in Replay
**What the flying port did before.**
- `AP_OpticalFlow_MAV` averages `AP::ahrs().get_gyro()` over the messages of each flow sample
  (`AP_OpticalFlow_MAV.cpp:36-76`). So `rawGyroRates`, which is also `ROFH.G`, is the INS-filtered gyro plus the drift
  of whichever AHRS backend is ACTIVE:
  - `AHRS_EKF_TYPE 12`: the UKF's own drift (`AP_AHRS_UKF`: `gyro + drift`, with drift = −UKF bias);
  - `3`: EKF3's drift (`AP_AHRS.cpp:818-822`);
  - `10`: zero (`AP_AHRS_SIM.cpp:216`).
- The port used that gyro as delivered, both flying and in Replay. So in a Replay of an EKF3-flown log, or onboard in
  shadow under EKF3, it derotated with **EKF3's** bias.

**The rule now, in `NavUKF::writeOptFlowMeas`.**
- If the active backend is this UKF, the paired gyro is used as delivered, with no arithmetic. This is bit-for-bit
  the `gyro + drift` that `AP_AHRS_UKF` gives.
- Otherwise the active backend's bias is swapped for the UKF's own:
  `g = raw + (b_active − b_own)` on x/y, where `b_own = gyro_bias_rate()` at arrival, and 0 before initialisation.
- **Flying:** `AP_AHRS` passes `-get_gyro_drift()` and `active_EKF_type() == UKF`. So a DCM fallback is also handled
  exactly.
- **Replay:** the active backend comes from the log's `AHRS_EKF_TYPE`:
  - 12: as delivered;
  - 3: the Replay EKF3's primary-core `getGyroBias(-1)`, passed read-only by the DAL `ROFH` handler. This is the same
    call `AP_AHRS::update_EKF3` uses;
  - 10: zero;
  - anything else, or no PARM: as delivered, with a printed warning and a line in `ukf_derot.csv`.
- **The FLOW_TYPE gate (`16535f9a29`).** The swap is valid only for flow drivers whose body rate is the AHRS gyro.
  - **Swapped:** Pixart 2, CXOF 4, MAVLink 5, MSP 7, UPFLOW 8 (`AP_OpticalFlow_*.cpp` at 7bac20cbcc).
  - **Used as delivered**, with one GCS warning and a `warning_flow_type_not_ahrs_gyro` line in `ukf_derot.csv`:
    PX4Flow 1, Bebop 3, HereFlow 6 and SITL 10, which send the sensor's own gyro with no AHRS bias, and any unknown
    FLOW_TYPE. **The rule for these needs a ruling.**
  - **Where FLOW_TYPE comes from:** the log's PARM in Replay; on a vehicle, `AP_Param`, read once at the first flow
    sample.
- **`UKF_DEROT_ROFH=1`** restores the old rule, for regression.
- Replay writes **`ukf_derot.csv`**: per flow, the rule, b_active, b_own and the gyro used. `ukf_inputs.csv` keeps
  the delivered gyro, and `ukf_shadow.csv`'s format is unchanged.
- **Declared approximations:**
  - The flight driver samples the active drift at each MAV message arrival, while the port reads `b_own`/`b_active`
    at `writeOptFlowMeas` time.
  - In Replay of a type-12 log, the periods before the flying UKF became the active backend cannot be distinguished,
    so they are used as delivered. Pre-initialisation flows are not fused, so at most the first post-initialisation
    sample is affected.
  - The INS 20 Hz-filtered gyro itself is kept as before. The DAL holds no copy of it, so Replay cannot rebuild it,
    and the ruling changes only the bias.
  - **Multi-IMU boards (not exercised in SITL).** `b_active` is EKF3's primary-core bias, and `ROFH.G` comes from
    that core's IMU. The UKF's `b_own` is for `get_first_usable_gyro()`. If the two IMUs differ, the swap mixes IMUs.
    Check this on the real board (`EK3_IMU_MASK`, the primary core).
- The take-off detector already used `|ω − b_own|`. `UKF_Equiv` takes the tape's corrected rate directly, so there is
  no double correction.
