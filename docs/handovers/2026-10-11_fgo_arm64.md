## 3. Correctness (pre-statement `PRE_STATEMENT.md`, written before the runs)
- **Probe:** every factor `[A|b]` is bit-identical to x86. The preintegration and retract differ at the last bit.
- **dsn_tex_r1_baseline, the whole flight:**
  - 10197/10197 keyframes, 0 flag mismatches;
  - 0/2039 gate mismatches (63/63 fired);
  - max / p99 |Δp| 0.074 / 0.0083 mm, |Δyaw| 4.3e-5°.
- **fwdc_tex_r1_heading:** 10118/10118 keyframes, heading accepted 9184 in both, 0 gate mismatches, max |Δp| 1.3e-4 mm.
- **Caveat:** on dsn_tex the closest gate check is 2.4e-6 from the 0.04 threshold, and the ARM-x86 trace difference
  reaches 6e-6. **The band C threshold-tie mechanism therefore applies across architectures too.** It did not flip
  here, but it could on another stream. This bears on the pending band C ruling, since a Pi would be another
  "different stream".

## 4. Timing
- **qemu:** a median of 22–28 ms per keyframe, 31–42× x86. This is RELATIVE ONLY; the workload-dependent ratio shows
  that it is not a Pi predictor.
- **Pi:** ESTIMATED from the x86 step times (2d replays and the L1/L2 live logs) × Geekbench 6 single-core ratios
  (`docs/fgo_cpp_port.md`; Pi 5 1.9–2.0×, Pi 4 4.5–5.2×). Table in `RESULTS.md` and `pi_estimate.txt`.
  - Pi 5: median ≤ 1.9 ms, p99 ≤ 3.4 ms.
  - Pi 4: median ≤ 5.0 ms, p99 ≤ 8.8 ms.
  - The budget is 33 ms. The one recorded 12.9 ms spike scales to ~25 ms on a Pi 5 and ~58–67 ms on a Pi 4.

## 5. What needs the real Pi
1. **The true timing and thermal throttling:**
   - a native run of `fgo_cpp_replay` on the same exports, which should reproduce the qemu arm64 outputs;
   - timing under the full load (flow tracker, UKF, heading) with `taskset` pinning and RT priority;
   - a sustained run with active cooling and logged `vcgencmd measure_temp` / `get_throttled`.
2. **Memory:** the true RSS (qemu peak 43–48 MB includes the emulator) and the Pi 4 RAM variant. A native build on
   a Pi 4 needs `-j2` and swap; or deploy the cross-built libraries.
3. **The serial/UDP link to the FC** (G9): the ODOMETRY output path and its latency.
4. **The camera pipeline** (rung 2, PARKED).
5. **The systemd service** (start order, restart policy, the self-stop → backend invalid → LAND path).
6. **Clock sync** between the Pi and the FC (`/imu/time_ref` stamping, `FGO_CPP_IMU_STAMP=time_ref`).
7. Also: **`fgo_cpp_node` itself** needs ROS 2 Jazzy arm64 (Ubuntu 24.04 on the Pi). It was not cross-built.
