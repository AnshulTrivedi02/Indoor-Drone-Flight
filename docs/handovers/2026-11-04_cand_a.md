### Architecture

- Shared code (`rd`, `rng`, `sim_path`, `cl_clock`, `cl_yaw_err`, `cl_meta`, `C`/`MK`/`TRUTH`/`EST`/`HALF`/`WIN`) is
  **ast-parsed from `eval/figs_thesis.py`**, not executed as a script and not imported - the same technique
  `eval/figs_walkthrough_flights.py` uses, so this script cannot silently drift from the thesis figures' own values.
- `cached()`/`ex_cl()`/`ex_room()`/`ex_sim()`/`ex_xkf1()`/`_bag_open()`, `aligned`-adjacent helpers (`to_NE`, `NE`,
  `frame_ok`, `unaligned`, `gt_enu`) are COPIED from `eval/figs_walkthrough_flights.py` (itself copied from
  `eval/figs_thesis_drift.py`/`_results.py`), not invented.
- Its own `save()`/`check()`/`cite()`/`write_caption()` mirror `eval/figs_thesis.py`'s, writing to
  `docs/thesis/figures_thesis/candidates/` instead (NOT `thesis_style.write_caption()`, which hard-codes
  `figures_thesis/captions/` - using it would have perturbed `caption_verdict_check`'s file count).
- A local copy of the D113 banned-word regex self-checks every caption body before `save()` writes it (the
  coordinator's `caption_verdict_check.py` does not yet scan `candidates/`, per the group brief).
- **Height autocrop** (`save()`): several candidates lock an axes box to a 1:1 data aspect (`adjustable="box"`),
  which leaves a lot of dead vertical margin in a fixed-height figure - the same mechanism the restyle's R3/R5 fix
  addressed. Rather than hand-tuning `figsize` per figure, `save()` crops the SAVED bbox to the figure's own actual
  content height, at the FULL declared width (`0` to `TEXT_WIDTH_IN`) - every PDF is still exactly 453.6 pt wide
  (confirmed: `pdfinfo` on all 20), unlike `bbox_inches="tight"` (which the restyle banned because it also changes
  the width).

### Defect 2: A13 "wall" labels overflowed their band; panels had excess vertical gap

Root cause for the label overflow, confirmed by computation, not just eyeballing: `wallband()`'s "wall" text is
centred in the data-coordinate band (East = 10 to `LIMC`), but each of A13's 3 panels has `set_aspect(1.0,
adjustable="box")` with an x-range of 182 m rendered at a 160 mm page width - that pins the point-per-metre
scale (~2.3 pt/m at the actual rendered axes width) in BOTH directions. At the old `LIMC = 12.5`, the band was
only 2.5 m (East 10-12.5) = roughly 6 pt tall, physically smaller than even a 7.5 pt label, so the text
overflowed the band's top/bottom edges in both panels regardless of exact anchoring - no placement tweak alone
could have fixed it without widening the band. Widened `LIMC` to 17.0 (band = 7 m = comfortably >20 pt at this
scale) and raised the label to 9.5 pt (regular weight, matching the >=9 pt / not-touching-any-line requirement);
re-checked by eye that no "wall" label touches the dotted boundary or the panel frame in any of the 3 panels.

The panel-spacing half of the same defect was a second, independent effect of the same equal-aspect mechanism:
with `adjustable="box"`, matplotlib shrinks each panel's axes box to the aspect-correct height within its
allotted GridSpec cell, centred, leaving the rest of the cell blank - the old `figsize=(..., 5.9)` with no
explicit `hspace` had guessed a cell height far larger than the aspect-correct content needed, so most of the
"gap" between panels was dead cell padding, not blank margin added on purpose. Reduced `figsize` height to 4.5
and set `gridspec_kw={"hspace": 0.28}` explicitly; re-ran and confirmed the panels now sit close with no
touching between a panel's own content and the next panel's tick labels.
