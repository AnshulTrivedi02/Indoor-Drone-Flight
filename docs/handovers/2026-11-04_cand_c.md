## Design notes / judgement calls

- **Shared check pool for C02/C03** (`save(..., pool="C0203")`): `allowed_for(fid)` filters `CHK` by exact fid, so
  C02's chart and C03's table draw numbers from one shared pool of data-identity checks (`ROW3`, `REF3`, `VREF`,
  the per-group diverged/collapsed counts) registered once under `"C0203"`, rather than duplicating every check
  twice. `guard()`/`save()` take an explicit `pool=` override for this.
- **Number guard extended to captions and tables, not just drawn figure text** (advisor-suggested, not in the
  existing restyle scripts): `guard(fid, text)` applies the same NUMTOK stray-number check to caption bodies and
  markdown table cells as `save()` applies to on-canvas text. This caught several real gaps during the build (room
  geometry numbers mentioned only in prose, band values like the 1.10 in P-E3b.1, the registered-id self-references)
  that would otherwise have been uncross-checked numbers sitting in a caption or table file.
- **`_strip()` fix for composite "fake numbers" in identifiers**: registered-hypothesis ids (`P-E3.5a`, `H-E2.1`,
  `P-E3b.1`) and this group's own candidate ids (`C02`, `C03_table.md`) contain digit sequences that `NUMTOK` would
  otherwise demand a check for (e.g. the `3.5` inside `P-E3.5a`). Stripped before scanning via `ID_RE`/`CAND_RE`,
  the same fix the restyle generators already apply to `EKF3` (-> `EKF`, so its `3` isn't mistaken for a claimed
  value). Genuine claim numbers (the `1.5` in "<= 1.5 x lap-1", the `1.10` in P-E3b.1's band) are untouched by this
  and still require their own passing check.
- **C04's registered-verdict table is a markdown table candidate, not a chart** (brief: "verdicts belong in
  tables, not on figures"). Its own `.md` file legitimately carries PASS/FAIL words, the same convention as
  `TA_verdicts.md`/A1-A3; only its **caption** file (`captions/C04.md`) stays D113-clean (no verdict words, ends in
  the pointer line) -- the caption describes the table, the table itself carries the verdicts.
- **C04 flags the P-E3b.1 (1%) "SATISFIED, flagged" qualification** (found in advisor review): 6 of its 9 passing
  runs have no matched plain-arm run to compute a ratio against (it diverged), per the 2026-10-23 user ruling
  recorded in `e3_results.md` and TA row 73. Added as a `note` column on that row rather than silently dropping the
  qualification the source register carries.
- **C05/C06 pointer is `none (descriptive)`, not `H-E3.1`** (corrected in advisor review): each panel is ONE run,
  while H-E3.1 is scored over the 9-run population, and C05's left panel is Experiment 3 (no wrong IDs at all), not
  an Extension E3 run. Pointing at H-E3.1 would have been exactly the kind of over-claim the restyle handover
  records being fixed on R3/R5 (a descriptive single-flight figure wrongly claiming a population-level hypothesis
  row).
- **"Whole-flight re-solve" / "whole-flight batch" wording corrected** (advisor review): the FGO hindsight drawn in
  C01/C05/C06/C07 is sourced from the tier1/Experiment-3 `hindsight.tum` pipeline, which `docs/thesis/tier1/
  e5_design.md:247` and `TA_verdicts.md` row 84 state is **iSAM2's full-graph estimate after 5 extra updates, not an
  LM batch** -- that is a DIFFERENT mechanism from Experiment 2's own separately-labelled "FGO hindsight
  (whole-flight batch)" (`e2_results.md:94`), which Extension E2's own B/C/D conditions do not use either (they
  reuse the same tier1 hindsight mechanism as Experiment 3). All four captions/legends now say "hindsight (after
  landing)" rather than implying an LM re-solve, with C07 citing the iSAM2 mapping explicitly.
- **C02's grey no-LC reference band and legend moved below the axes**: the "diverged" tick-label band at the top of
  the axis left no clean space for an in-axes legend without it sitting on top of either the diverged marks or the
  5%-group data points, which the brief's no-overlap rule forbids. Legend placed outside the axes
  (`fig.legend(loc="lower center", ...)`) with `tight_layout(rect=...)` reserving the space, the same pattern
  `e3_maps()` already uses for its own legend.
- **9 pt font floor enforced in `save()`**: added an explicit `assert t_.get_fontsize() >= 9.0` over every visible
  `Text` artist (caught by the advisor review -- several legends/tick labels/panel titles were originally at
  8.0-8.6 pt). All five chart candidates were re-laid-out afterwards (wider figures, `ncol` legends, `fig.legend`

  the identical stored files -- so the check is a genuine two-pipeline agreement, not a tautology. That file is read
  only, never regenerated or modified by this script.
- **Every caption now states raw or fitted explicitly** (advisor review, second round; the brief's caption spec

### Defect fixed: C02's diverged-run markers overlapped

**Symptom**: in the "1% wrong IDs, FGO as built (plain)" column, 6 of the 9 runs diverged and were drawn as "x"
markers at the shared categorical "diverged" row (`YDIV`). All six were assigned x-positions from the same
9-point `linspace(j - 0.32, j + 0.32, 9)` used for the live (finished) runs in that column, so the six diverged
positions (indices 1, 2, 4, 5, 7, 8 of that linspace) had gaps as small as 0.08 data units -- visibly smaller
than the marker width at this figure's scale, so several "x" marks rendered on top of each other and were not
individually distinguishable.

**Fix** (`eval/figs_cand_c.py`, the C02 plotting block): live and diverged runs within a column now get their own
independent, deterministic horizontal spread instead of sharing index slots in one linspace over all runs in the
group. Live runs keep the original `linspace(j - 0.32, j + 0.32, n_live)`; diverged runs get their own
`linspace(j - 0.4, j + 0.4, n_diverged)` (falls back to a single point at `j` when a span can't be computed, i.e.
0 or 1 runs of that kind). The wider diverged span still fits inside the 1.0-unit column pitch, so it stays clear
of the neighbouring column at `j + 1` (whose live/diverged runs start no earlier than `j + 1 - 0.4 = j + 0.6`).
Ordering is still the `runs3()` sort (alphabetical by run name), so which physical run lands at which x-position
is deterministic and unchanged in meaning, just no longer sharing slots with the live subset.

Re-rendered and viewed `C02.png`: all six "x" markers in the affected column are now individually visible and
separately spaced, with no overlap among themselves and no encroachment into the "1% wrong IDs, robust FGO"
column. No other column in C02 has more than one diverged run (`arm (a) 5%`: 0 diverged; `arm (b)`, every rate:
0 of 21 diverged -- see the `C0203` checks), so this was the only affected spot in the whole candidate set.
